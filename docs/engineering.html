Chapter 1

Ground rules

The handful of rules that shape almost every design decision.

Rules of thumb

Ten rules

  1. AI output is untrusted input
  2. Authorization lives in application code, not in prompts
  3. Tenant id comes from trusted context only
  4. Provider details stay in adapters
  5. Commit durable state before acknowledging
  1. No DB transaction while waiting on an LLM or provider
  2. Every external call: timeout, bounded retry, idempotency
  3. Streaming tokens are not a committed message
  4. Never claim an action succeeded until the tool confirms
  5. Store decision metadata, not hidden reasoning
Never

Things that look convenient and are not

  • Trust a tenant id from a request body
  • Give the model raw credentials or open HTTP access
  • Let retrieved documents change system policy
  • Retry a write blindly after a timeout
  • Put message text, email or phone in metric labels
  • Share one Postgres transaction with a slow external call

Tools: registry and execution

Connectors and secrets

Illustrative sketch, not final code

One tool call, all the rules

async function executeTool(ctx: TenantContext, call: ToolCall) {
  const tool = registry.resolve(ctx.agentVersionId, call.name);  // allowlist
  const args = tool.inputSchema.parse(call.arguments);            // validate
  await authz.require(ctx, tool.requiredPermission);              // trusted context

  const prior = await executions.byKey(ctx.tenantId, call.idempotencyKey);
  if (prior?.status === "succeeded") return prior.result;         // no second call

  const exec = await executions.start(ctx, tool, args);           // no open tx below
  try {
    const raw = await connector.call(tool.operation, args, { timeoutMs: tool.timeoutMs });
    return await executions.succeed(exec, tool.outputSchema.parse(raw));
  } catch (e) {
    return await executions.fail(exec, mapError(e)); // write timeout => UNKNOWN_OUTCOME
  }
}

Security checklist

Run on every release

  • Cross-tenant read and write
  • Unauthorized tool invocation
  • Prompt injection: input and documents
  • Webhook signature failure and replay
  • Duplicate webhook delivery
  • Tool timeout, unknown write outcome
  • Secret leakage in logs and traces
  • Unauthorized transcript or audio access
  • Rate limit and abuse
