\section{Logical layers}

Seven layers organize the system: (1) edge and channel adapters; (2) application API (authentication, tenant resolution, validation, rate limiting); (3) conversation domain; (4) AI orchestration; (5) capability modules (knowledge, business tools, workflow, tickets, human inbox); (6) infrastructure adapters (SQL, object storage, vector index, queue, providers); (7) cross-cutting controls (security, audit, observability, evaluation, usage metering).

\section{Main functional flow (nominal journey)}
The following journey describes one text conversation turn in the MVP.
\begin{enumerate}
  \item The visitor opens the widget: a scoped session is created and the conversation is attached to the right tenant and channel (M02, M01, M18).
  \item The visitor sends a message: it is received, deduplicated and durably persisted before acknowledgement (M02, M01).
  \item The AI engine resolves trusted context (tenant, conversation, identity, agent version) and checks the conversation state: open, human-owned, blocked or rate-limited (M04).
  \item It builds a minimal context, classifies intent and risk, and identifies missing information (M04).
  \item When useful, it retrieves approved, tenant-filtered knowledge (M05).
  \item It plans the next step using \emph{only} the agent's allowed tools; any proposed tool call is validated, authorized, then executed (M06).
  \item It generates a response based on verified results, applies output-safety rules, and persists the reply, sources, tool results, timing, usage and outcome (M04, M01).
  \item Delivery, evaluation and analytics events are emitted (M02, M16, M20).
  \item If policy requires it or the customer asks, the conversation is handed to a human with its context (M10).
\end{enumerate}

\section{Possible engine decisions}
At each turn the engine chooses one of the following outcomes:
\begin{itemize}
  \item answer from approved knowledge;
  \item ask a clarifying question;
  \item invoke an allowed business tool;
  \item create or update a ticket or workflow request;
  \item refuse or safely redirect a disallowed request;
  \item hand off to a human;
  \item recover from a provider or tool failure.
\end{itemize}

\section{Multimodal conversations}
A conversation can contain: customer text messages, finalized speech transcripts, assistant text, generated audio references, system events (voice started or ended) and handoff events. The engine consumes normalized text and intent plus trusted state, without depending on whether the text was typed or transcribed.
