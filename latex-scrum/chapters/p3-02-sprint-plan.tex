\section{Sprint 0 / Enablement (only if needed)}

\textbf{Sprint Goal:} make the team able to build, test, and release safely.

\begin{itemize}
\item Repository and module/package structure
\item CI pipeline, formatting, static analysis, test setup
\item Local development environment and database migrations
\item Initial threat model and architecture decision records
\item Minimal deployment and secret handling
\item Definition of Done agreement
\end{itemize}
Do not use Sprint 0 as a permanent phase that postpones delivering product value.

\section{Sprint 1 --- Secure conversation foundation}

\textbf{Sprint Goal:} a tenant-scoped conversation and message can be created, persisted, and retrieved.

\begin{itemize}
\item US-001 organization foundation
\item US-003 tenant-isolation test foundation
\item US-010 conversation creation
\item US-011 text message persistence
\item Initial audit/correlation ID conventions
\end{itemize}

\section{Later Sprints}

\begin{itemize}
\item Additional channels/connectors
\item Workflow builder, routing, SLA, notifications
\item Advanced evaluation and release gates
\item Usage plans, quotas and billing
\item Additional organization administration and reporting
\end{itemize}
\section{Planning caveats}

\begin{itemize}
\item Team size and capacity are unknown; sprint count may change substantially.
\item Voice and integration work often depend on vendor capabilities and credentials.
\item Pull security, observability, and tests into each Sprint rather than deferring them.
\item Each Sprint should end with a usable Increment, not only design documents.
\end{itemize}
